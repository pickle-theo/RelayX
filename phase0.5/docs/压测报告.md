## 2. 压测参数

服务端：

```powershell
.\bin\gateway.exe -addr 127.0.0.1:19100 -stats-interval 5s
```

客户端：

```powershell
.\bin\loadtest.exe -addr 127.0.0.1:19100 -conns 1000 -duration 60s -interval 1s -ramp 5s -out docs\loadtest-result.txt
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `-conns` | 1000 | 并发连接数 |
| `-duration` | 60s | 压测总时长（含 5s 建连 ramp） |
| `-interval` | 1s | 每连接每秒发送 1 个 DATA 帧 |
| `-payload-size` | 64 B | 固定 payload 长度（Body 前缀为 `load#<connID>#<seq> `） |
| `-ramp` | 5s | 1000 条连接在 5s 内均匀建立 |
| `-timeout` | 5s | 单次回显等待超时 |
| `-max-body` | 1 MiB | 与服务端默认值一致 |
| 服务端其他参数 | 默认值 | 心跳 30s、心跳超时 90s、空闲超时 120s、发送队列 256 帧 / 4 MiB、批量写 16 帧 / 64 KiB、写超时 10s、读缓冲 4096 B |

## 5. 与 Phase 0 对比

| 指标 | Phase 0 | Phase 0.5 | 变化 |
| --- | --- | --- | --- |
| 连接成功率 | 100.00%（1000/1000） | 100.00%（1000/1000） | 持平 |
| sent / echoed / missed | 57003 / 57003 / 0 | 57003 / 57003 / 0 | 持平 |
| 错误计数（连接/超时/解码/非预期/写） | 全 0 | 全 0 | 持平 |
| RTT P50 / P90 | 0.000 / 0.000 ms | 0.000 / 0.000 ms | 持平（均低于时钟粒度） |
| RTT P99 | 0.000 ms（低于时钟粒度） | 0.537 ms（≈1 个时钟刻度） | 尾部可分辨值上升 |
| RTT 最大 / 平均 | 9.860 / 0.006 ms | 35.560 / 0.043 ms（复测 3.844 / 0.015） | 波动，见下 |
| 服务端 goroutine 峰值 | 3004 | **2004** | **−1000（−33.3%）** |
| 每连接服务端协程 | 3（读 + 写 + 心跳） | 2（读 + 写，心跳并入写） | −1 |
| 服务端 heap_alloc 峰值 | 28.26 MB | 26.79 MB（复测 27.74 MB） | −1.47 MB（−5.2%） |
| 服务端 heap_sys 峰值 | 36.34 MB | 36.16 MB（复测 40.16 MB） | ≈持平 |
| 客户端 heap_alloc | 3.17 MB | 3.30 MB | +0.13 MB |
| 客户端 goroutine | 2001 → 1 | 2001 → 1 | 持平 |
| 数据帧写 syscall | 1 次/帧 | 10 帧 1 次（`TestWriteCallsBatched`） | 显著减少 |

解读：

1. **吞吐与正确性没有回退**：同参数下发送/回显条数与 Phase 0 完全一致（57003/57003），错误计数全 0，说明批量写、池化与 ctrlCh 优先没有引入丢帧或乱序（`TestControlFramePriority`、`TestWriteCallsBatched` 逐帧校验顺序）。
2. **协程数按设计下降 1/3**：心跳从独立协程并入 writeLoop 的 `time.Timer`，1000 连接由 3004 降到 2004，直接降低了调度与栈内存开销。
3. **服务端堆峰值小幅下降**：26.79 MB vs 28.26 MB。池化把每帧的编码缓冲复用起来，但 `sync.Pool.Put([]byte)` 的装箱（约 24 B/次）与池的 per-P 缓存会保留一部分缓冲，因此下降幅度有限。
4. **RTT 尾部存在可复现的小幅上升**：Phase 0 的 P99 无法被 505 µs 时钟分辨（0.000），Phase 0.5 两轮均为约 0.535 ms。由于 P50/P90 仍为 0.000，这表示约 1% 的往返多跨了一个时钟刻度；可能来源是写路径每批新增的 `SetWriteDeadline` + 清除、批量拼接的一次拷贝，或单轮采样噪声。该差异小于一个时钟刻度，无法用本机时钟量化，不能据此断言真实延迟回退，但也不应被隐藏；需要在更高分辨率平台做多轮验证（见第 7 节）。
5. **最大 RTT 波动大**：35.560 ms 与复测 3.844 ms 相差近 10 倍，属于调度/GC 抖动，不是稳定指标。

## 6. 结论

1. 在本机回环、1000 并发连接、每秒 1000 帧、60s 条件下：连接成功率 100%，57003 条 DATA 全部收到回显，超时/解码/非预期帧/写错误均为 0，`loadtest` 退出码 0，与 Phase 0 吞吐完全一致。
2. 每连接服务端协程由 3 降为 2，1000 连接的服务端 goroutine 峰值由 3004 降至 2004（−33.3%），是本次优化最明确、可复现的收益。
3. 服务端堆内存峰值小幅下降（28.26 → 26.79 MB），批量写把 10 帧合并为 1 次 `Write`（单测证据），但本报告的压测指标无法直接测量 syscall 次数。
4. 正确性与生命周期未受影响：压测中无 `send queue full`、`write timeout`、`heartbeat timeout`；客户端收尾后 goroutine 回落为 1，端口 19100 释放，无残留 gateway 进程。
5. RTT 尾部（P99）在本机时钟粒度下由"不可分辨"变为约 0.5 ms，需在更高分辨率环境复核后再判断是否真实回退。

## 7. 已知限制

1. **仅本机回环**：延迟为本地协议栈往返，不含真实网络 RTT、丢包与重传；客户端与服务端共享同一颗 8 线程 CPU，存在互相抢占。
2. **RTT 分辨率受限**：本机单调时钟粒度约 505 µs，亚毫秒的 P50/P90/P99 无法精确分辨，只能给出"低于/约等于一个刻度"的结论。
3. **单轮采样**：主结果为单轮 60s，尾部指标受环境噪声影响；已补跑一轮复测用于判断稳定性，但仍不足以作为长期基线。
4. **时长短于多个心跳周期**：60s 仅覆盖约 2 次服务端 PING，未验证长时间空闲下的心跳超时清理与 90s 心跳超时路径（该路径由 `TestHeartbeatTimeoutClosesConn` 单测覆盖）。
5. **未覆盖大帧、突发流量、慢消费者与发送队列打满**：载荷固定 64 B、每秒 1 帧，`send-queue-bytes` / `write-batch-bytes` 的边界由单测（`TestSendQueueByteBudget`、`TestWriteCallsBatched`）覆盖，未做端到端压测。
6. **竞态检测范围**：`-race` 只覆盖单元/集成测试，gateway 与 loadtest 二进制未以 `-race` 构建，因此本报告容量数据不代表 race 模式下的性能。
7. **服务端收尾数据不完整**：压测结束后立即按 PID 停止进程，未采集"全部连接断开后"的 stats；773 条关闭日志（766 peer closed + 7 RST）也少于 1000，原因是部分连接的关闭日志尚未写出进程即被停止。
8. **压测工具自身统计口径**：连接关闭瞬间的 PONG 写失败被识别为 `net.ErrClosed`，不计入 `write_errors`；本次为 0。

## 9. 复现方式

```powershell
# 构建
New-Item -ItemType Directory -Force -Path bin | Out-Null
go build -o bin/gateway.exe ./cmd/gateway
go build -o bin/loadtest.exe ./cmd/loadtest
go build -o bin/client.exe ./cmd/client

# 后台启动服务端（slog 写 stderr，stdout 只有 listening 行，两者都落盘）
$gw = Start-Process -FilePath "$PWD\bin\gateway.exe" `
    -ArgumentList "-addr","127.0.0.1:19100","-stats-interval","5s" `
    -RedirectStandardOutput "$PWD\docs\gateway-stdout.log" `
    -RedirectStandardError "$PWD\docs\gateway-run.log" `
    -PassThru -WindowStyle Hidden
Start-Sleep -Seconds 2

# 压测
.\bin\loadtest.exe -addr 127.0.0.1:19100 -conns 1000 -duration 60s -interval 1s -ramp 5s -out docs\loadtest-result.txt

# 按实际 PID 停止服务端，避免误杀同名进程；再确认端口释放
Stop-Process -Id $gw.Id -Force
Test-NetConnection 127.0.0.1 -Port 19100   # TcpTestSucceeded = False
```
