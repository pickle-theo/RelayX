# ADR-0004：Sequence 连接内单调、不回绕、不作去重键

- 状态：Accepted（S0 冻结）
- 契约来源：S0 LLD §3.4 / §4；架构方案 §4.1 身份与幂等

## 背景

需要给每个出站帧一个可观测的序号，用于排查乱序、跳号与丢帧。但必须避免把它误用成业务去重键——真正的幂等键由语义契约定义（接入 `(tenant_id, producer_id, client_msg_id)`，投递 `(tenant_id, message_id, user_id, device_id)`），与传输序号无关。

## 决策

- `SequenceTracker` 每条连接一个实例，从 1 开始单调递增，`uint32` 不回绕。
- 到达 `math.MaxUint32` 后 `Next()` 返回 `ErrSequenceExhausted`，连接必须断开，而不是回绕到 0。
- Sequence 仅用于传输层可观测性；S1 起用于乱序/跳号观测。任何业务层都不以它去重。
- 入站帧携带的 Sequence 不被服务端校验连续性——允许观测到的跳号由转发路径或客户端行为造成，不在传输层判定为错误。

## 后果

- 永不回绕消除了序号复用导致的观测歧义。
- 幂等责任被清晰地留在语义层（`message_id` / `client_msg_id`），传输层不越界做业务判断，符合平台「传输事实提供者」的边界。
- 长连接帧数触及 2^32 时断连，属于可接受的极低频事件，换来序号语义的单一明确含义。
