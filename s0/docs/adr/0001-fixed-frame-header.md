# ADR-0001：定长 14 字节帧头 + CRC 覆盖头部

- 状态：Accepted（S0 冻结）
- 契约来源：S0 LLD §3.1、§4

## 背景

传输层需要把字节流切分成帧，并且在字段被传输损坏时能快速识别、拒绝，而不是把损坏的 Length 当作真实长度去分配内存。帧头结构一旦冻结，S1–S8 只能扩展 Type 与 Body，不能回头改，因此必须在起点定型。

## 决策

- 帧头固定 14 字节：`Magic(2) | Version(1) | Type(1) | Length(4, BE) | Sequence(4, BE) | CRC16(2)`。
- Magic 固定 `0x52 0x58`（"RX"），用于帧对齐与非法连接快速识别。
- CRC16/CCITT-FALSE（初值 `0xFFFF`，多项式 `0x1021`，不反射）只覆盖头部前 12 字节，保护 Length 与 Sequence 字段。
- Body 不参与 CRC：它是对业务不透明的字节，其完整性由上层语义（S2 起）负责；头部 CRC 足以防止按错误长度切帧。

## 后果

- 解码可在读到 14 字节后立即校验协议合法性与头部完整性，早于任何 Body 分配。
- CRC 不覆盖 Body，故单帧 Body 内的位翻转不会被传输层发现——这是有意的分层，避免与上层校验重复。
- 头部长度是冻结契约；任何字段增减都要重开冻结线并让所有阶段重测。
