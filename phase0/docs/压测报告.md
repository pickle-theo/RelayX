## 2. 压测参数

服务端：

```powershell
.\bin\gateway.exe -addr 127.0.0.1:19100 -stats-interval 5s
```

客户端：

```powershell
.\bin\loadtest.exe -addr 127.0.0.1:19100 -conns 1000 -duration 60s -interval 1s -ramp 5s
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `-conns` | 1000 | 并发连接数 |
| `-duration` | 60s | 压测总时长（含 5s 建连 ramp） |
| `-interval` | 1s | 每连接每秒发送 1 个 DATA 帧 |
| `-payload-size` | 64 B | 固定 payload 长度（Body 前缀为 `load#<connID>#<seq> `） |
| `-ramp` | 5s | 1000 条连接在 5s 内均匀建立 |
| `-timeout` | 5s | 单次回显等待超时 |
| `-max-body` | 1 MiB | 与服务端默认值一致 |
| 服务端其他参数 | 默认值 | 心跳 30s、心跳超时 90s、空闲超时 120s、发送队列 256 |

### 3.4 RTT（毫秒）

| 指标 | 值 |
| --- | --- |
| 样本数 | 57003 |
| P50 | 0.000 |
| P90 | 0.000 |
| P99 | 0.000 |
| 最大值 | 9.860 |
| 平均值 | 0.006 |

> 读数说明：本机 Windows 单调时钟粒度实测约 505 µs（用一个仅调用 `time.Now()` 的独立程序测量相邻两次读数的差值分布，绝大多数为 0，最小非零间隔 412.8 µs–506 µs）。用同一环境下单连接 TCP 往返探测（一次 `Write` + 一次读回完整帧）得到的 `time.Since` 也全部为 0。因此表中 0.000 表示"低于该时钟可分辨的下限（约 0.5 ms）"，并非真实 RTT 为 0；平均值 0.006 ms（6 µs）与最大值 9.86 ms 说明绝大多数往返在微秒级、极少数被调度或 GC 拉长。更精细的亚毫秒分位数需要在时钟分辨率更高的平台测量。

## 5. 结论

1. 在本机回环、1000 并发连接、每秒 1000 帧、60s 的条件下：连接成功率 100%，57003 条 DATA 全部收到回显，超时/解码错误/非预期帧均为 0，`loadtest` 退出码为 0，满足 Phase 0 的单机容量目标。
2. 单连接开销约 28 KB 堆内存、3 个服务端协程；1000 连接下服务端堆内存峰值 28.26 MB，客户端堆内存 3.17 MB，资源曲线随连接数线性增长，无明显异常。
3. 心跳（30s）在 60s 窗口内只触发 1 次完整轮次：服务端在 t≈30s 与 t≈60s 发送 PING，客户端均在同一读循环内即时回 PONG，未出现心跳超时关闭。
4. 压测结束后服务端、客户端协程数均回落至基线，未发现连接或协程泄漏；端口 19100 已释放，无残留 `gateway` 进程。

## 6. 已知限制

1. **仅本机回环**：延迟为本地内存/协议栈往返，不含真实网络 RTT、丢包与重传，不能代表广域网表现；客户端与服务端共享同一颗 8 线程 CPU，存在互相抢占。
2. **RTT 分辨率受限**：本机时钟粒度约 505 µs，亚毫秒的 P50/P90/P99 无法分辨（见 3.4 说明），只能给出"低于 0.5 ms"的结论。
3. **时长短于多个心跳周期**：60s 仅覆盖约 2 次服务端 PING（t≈30s、t≈60s），未验证长时间空闲下的心跳超时清理与 90s 心跳超时路径。
4. **未覆盖 TLS/鉴权/真实业务负载**：Phase 0 无 TLS、无鉴权，载荷为固定 64 B 回显，未测试大帧、突发流量与发送队列打满（`send-queue-size` 背压）等场景。
5. **竞态检测范围**：`go test -race -count=2 ./...` 已通过本机 Docker 执行，但压测工具与 gateway 进程本身未以 `-race` 构建，因此上述容量数据不代表 race 模式下的性能。
6. **未做多轮重复**：本次为单轮 60s 采样，P99 等尾部指标受环境噪声影响，不宜作为稳定基线。
7. **压测工具自身的写错误归类**：连接关闭瞬间（服务端在 t≈60s 发送 PING，客户端此时正在收尾）可能出现的 PONG 写失败属于正常关闭，工具将其识别为 `net.ErrClosed` 而不计入 `write_errors`；首次调优前的一次试运行出现过 2 次该计数，修正后为 0。
