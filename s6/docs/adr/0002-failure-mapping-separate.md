# ADR-0002：转发失败映射与路由通道分离

- 状态：Accepted（S6）
- 关联：LLD §4.4、架构方案 I1

## 背景

跨节点转发失败可能来自多种原因：节点不可达、mTLS 失败、拨号超时、对端无会话、对端队列满。若把这些失败直接写成投递终态 `FAILED`，「节点暂时不可达」会被误判为「端点真的收不到」，破坏 At-Least-Once，并使消息级聚合守卫（`ACCEPTED → SETTLED` 要求无 PENDING/SENT 投递）永远无法满足。

## 决策

1. `internal/forward` 只负责「能不能把帧送到那个节点」，输出成功入队或带分类的失败；**不碰任何投递状态**。
2. `internal/dispatch.Outcome` 是 S6 与 S2 之间唯一接缝，固定 LLD §4.4 的 A–E 映射：
   - 转发失败 → 状态不变、attempts 不增、退避；
   - 只有对端已接收 FORWARD 才算一次真正尝试；
   - 连续 3 次不可达 → 清本地缓存、回落离线。
3. S2 语义层消费 `Outcome` 落库/写事实；S6 不实现 S2 状态机。

## 后果

- 正面：`FAILED` 只表示「端点真的收不到」，不再混入「刚好那个节点挂了」；路由抖动不会耗尽重试预算。
- 正面：S7 可复用 S6 的 mTLS 通道与寻址，但明确绕开 §4.4 策略（事件失败直接丢弃+计数），两者「共用通道、不共用策略」。
- 代价：调用方必须正确消费 `Outcome`；`test/failure` 用 100 轮并发竞态与失败分类测试守护这条边界。
