# ADR-0003：节点间通信第一次出现即启用 mTLS

- 状态：Accepted（S6）
- 关联：架构方案 I3、LLD §8

## 背景

S6 是平台第一次出现节点间通信。若先上明文临时方案、后续再补 TLS，会留下明文窗口，且所有中间调试工具/日志都可能固化对明文通道的依赖。I3 要求横切关注点在引入点落地。

## 决策

- 节点间 FORWARD 通道强制 mTLS：TLS 1.3 起、`RequireAndVerifyClientCert`、双向校验证书、内部 CA 签发。
- 不提供明文回退开关；校验失败即拒绝连接并审计日志。
- 密钥从 PEM 文件/环境变量读取，不落配置文件内容。
- `-dev-certs` 只生成临时自签证书用于本地验收，生产禁用。

## 后果

- 正面：不存在明文临时方案窗口；S8 只需补证书轮转/审计细化，不留安全债务。
- 代价：本地多节点验收需要生成临时 CA 与叶证书（`internal/forward/mtls.go` 的 `GenerateDevCA`/`GenerateDevLeaf`）。
- S7 跨节点广播/事件路由复用同一 mTLS 通道，无需重新审计传输安全。
