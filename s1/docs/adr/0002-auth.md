# ADR-0002：握手必鉴权，Producer 由令牌派生

- 状态：Accepted（S1 LLD §5 冻结语义）
- 背景：客户端连接是系统第一个外部接口（I3）。若留「先裸奔后补鉴权」窗口，
  后续所有业务路径都要重复校验身份，且难以封堵。

## 决策

- 连接建立后第一个业务帧必须是 LOGIN；未鉴权的连接发 SEND 会被拒（ERROR）。
- 令牌采用自包含 HMAC-SHA256 结构：`base64url(claims).base64url(sig)`，
  claims 含 tenant / name / kind / exp。密钥来自配置（S1 用共享静态密钥）。
- 校验通过后派生 `Producer{ID: u:<name> | svc:<name>, Kind, TenantID}`；
  `producer_id` 只存在于服务端会话中，SEND body 不含 producer 字段，客户端无法伪造。
- 鉴权失败发 `CLOSE`（body 空）并断开，不进入任何业务路径。

## 后果

- 身份边界清晰：S2 的幂等键 `(tenant_id, producer_id, client_msg_id)` 中的
  producer_id 来自可信派生，而非客户端声明。
- S1 仅最小实现：吊销名单、密钥轮转、审计在 S8 补齐；但「握手必鉴权」的
  语义在此定死，不会因后续增强而改动调用路径。
- 令牌过期用服务端本地时钟（鉴权范畴）；消息到期/超时的 SQL `now()` 仲裁
  属于 S2 语义契约，两者不混淆。
